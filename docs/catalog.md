# The catalog

How a world's catalog is read from the game, what an entry's kind and group are, and how entries are named.

Code: `src/Model/Naming.cs`, `src/Model/Entry.cs`, `src/Model/CodeWarmup.cs`, `src/Session.cs`, `src/Model/WorldCaches.cs`, `src/Model/WeatherWords.cs`, `src/Model/RaidGrouping.cs`, `src/Model/ToolBook.cs`.

See also: [search](search.md), [pages](details/pages.md), [reading](locations/reading.md); all notes in [the index](index.md).

## Reading the catalog

The catalog is read once per world, a few milliseconds each frame, starting ten seconds after the world is entered, so it is usually ready before the panel is first opened. Opened earlier, the panel says how far the reading has got, and the reading takes a bigger share of each frame while the panel waits. Nothing shows until all of it is read, since an entry's kind, links and groups are only known then.

Once a world's catalog is read, Scry compiles its own code ahead, 2 ms of each frame, the panel's, the skin's and the facts' first (`CodeWarmup`, `Session.Warm`). The runtime compiles a method the first time it is called, about a tenth of a millisecond each, so the first page drawn in a session, calling hundreds of methods for the first time, would take far longer than any after it. Every method with a body of its own is compiled, as its first call would, its type's methods looked up only as the warming reaches them; a type's static setup is not run by it. The runtime compiles generic code once for every class but anew for each value type it is given, so a generic method or type is compiled over object, the code any class it is first called with shares, and one that needs a value type or a particular class waits for its first call. What generic code does for a value type nothing can compile ahead: a LINQ ordering over a tuple brings its own iterators, sorters and comparers. So the code that tells a place's page gives its generic calls classes, numbers and names, never a tuple, a key and value pair or a nullable (`FirstUseStandardTests`), and the first dungeon picked in a session does not compile hundreds of methods in the frame that picks it.

It holds every prefab registered with the scene, every status effect in the object database, every raid the world has switched on, every location the world can place and every dungeon room it can build with, and every prefab reached through an effect list. Most sounds and many visual effects are never registered on their own: they hang off the effect lists of the items, attacks, pieces, creatures, status effects and interface that play them, so those lists are followed, including effects that point at further effects.

Leaving a world lets go of everything read of it. Each part of Scry that keeps something of a world registers how it forgets it (`WorldCaches`), and a test over Scry's own source fails when a store of world things is never emptied or its class never registers. A stricter one reads src/Catalog with the compiler's types (`SessionStateStandardTests`): every static field a class there changes, a collection something fills or a value written after it is made, is set, emptied or bumped by a reset registered with `WorldCaches`, or by a reset that one calls, or is listed as kept across worlds with why: a binding to the game's own code, the mods loaded, the character's book and walks, or a message registered on the game's router.

A prefab is the game's own when it was in the scene's lists before any mod ran, read by a first-priority prefix on `ZNetScene.Awake`, a status effect the same way on `ObjectDB.Awake`, a raid on `RandEventSystem.Awake` and `ZoneSystem.SetupLocations` (which adds the raids of the game's location lists), a location on `ZoneSystem.SetupLocations` and a room on `DungeonDB.SetupRooms`. An effect is the game's own when anything of the game plays it.

## Kinds and groups

An entry's kind comes from its components, what it does before how it looks: anything keeping a store (`Trader`) is a trader, Haldor, Hildir, the Bog Witch or a mod's, one a mod makes a creature too; anything else with a character is a creature, then projectiles, items and pieces. What spawns creatures, a nest (`SpawnArea`) or a spawn point (`CreatureSpawner`), is a spawner, though a nest breaks into drops; one a mod makes buildable is a piece. What is chopped, mined, picked or grown, or breaks into drops, is a resource. Something with only sound is a sound, particles or anything only ever played from an effect list are an effect, and the rest is other.

A mod that makes the game's own prefabs buildable (*MoreVanillaBuildPrefabs* adds a `Piece` to hundreds of them) does not change their kind. Such a mod leaves its `Piece` switched off on the prefab, which none of the game's own pieces is, so a ruin wall stays what the game made it, and its facts say the mod makes it buildable where a build tool's menu holds it (`Knowledge.Tools.ToolsOf`); the mod adds its piece to every prefab it can make buildable and puts in the menus only those its settings enable, so one it leaves out, as a bone pile in its creator shop with creative mode off, is told buildable nowhere. A crop planted with the cultivator is a piece, since it is built like one.

Each kind's tab groups its list by what the game itself says: items by their item type (weapons by the skill they train, armour by slot), pieces by the hammer's tabs and then by tool (a piece in several tools under the first, the hammer before the rest), creatures by faction, resources by how they are gathered, spawners into nests and spawn points, effects and sounds by the names of the effect lists that play them, projectiles by what fires them, and status effects by what gives them. The Creatures and Items tabs can group another way, one at a time, by a switch above the list (`ListGrouping`, `Explorer.Lens`, `ScryPanel.GroupBar`), each tab keeping its own: creatures by biome or by what taming allows, the most first (ridden where it takes a saddle, tamed and bred, tamed, summoned, of the players' faction but the player, and never tamed, which starts folded away), items by biome. By biome a thing stands once, under the first biome players reach, its row counting the biomes more it has; an item that neither spawns nor grows goes by the biomes of what gives it (`Entry.GiverBiomes`), and one with none under *No biome*. Under the compendium's strict rules a biome groups a thing only where the character met it there, the rest under *Not met in a biome yet*.

Raids are named by the message the game shows when they start and listed in three groups: the raids the game rolls for (by the raid roll or a timer of their own), then the bosses' fights, then what something else starts. A boss's fight is the event its `Character.m_bossEvent` names, which the game has on while the boss's health bar shows (`RandEventSystem.GetForcedEvent`, shown while the boss is alerted within `EnemyHud.m_maxShowDistanceBoss`), for its music and weather; it has no message, so it is named for its boss, its page goes to the boss and the boss's page to it, and Enter plays its music. A raid's or a fight's *Music* plays when clicked, as a place's does, and its *Weather* says what that weather does to whoever is out in it, as `EnvSetup` sets it: wet soaks you outside without a roof (`Player.UpdateEnvStatusEffects`), cold and freezing give their statuses by day or only at night, freezing outranking cold (`EnvMan.CalculateCold`, `CalculateFreezing`), some are always dark, and each blows within a range of wind (`WeatherWords`). Within a group they come in the order the bosses are fought: a fight by its boss's health, a raid by the health of the strongest boss whose defeat it waits for, those waiting for none first (`RaidGrouping`); boss health grows from Eikthyr to the Fader, so a mod's boss falls in place too.

Mods are listed by whether they add to the game, only hook into its drops or spawning, or neither, as far as Scry sees.

A build tool is any item with a build table (`m_buildPieces`): the hammer, the hoe, the cultivator and any mod's own. Every tool a piece is in is noted with the tab it is on there, named as the tool names it (`ToolBook`), so a piece says what builds it and on which tab, one tool as a link to it, several as chips, and a tool lists what it builds, a row for each of its tabs in its own order.

Locations are grouped by biome in the order players meet them, one placed in several biomes after those. A dungeon or camp and its rooms are one group of their own right after its biome's other places ("Black Forest · Burial Chambers"): the location first, tagged dungeon or camp with its prefab to tell its variants apart, then its rooms indented under it and tagged, entrances first, then rooms, then end caps, dividers and walls (`PlaceGrouping`, a rank within the group, `Entry.GroupRank`). A room has one home, the dungeon of its lowest theme flag (`Room.m_theme`), so a room two dungeons share (the Burial Chambers' and Hildir's crypt's) is under the first and names both. What kinds of room a dungeon is built of is in its location's bundle, so until a location building a theme is read (by selecting it, laying out its example, or reading every location) that theme's rooms wait together after every biome, under the theme's name.

What is no prefab is kept under a key of its own kind (`EntryKeys`: a status effect's "se:", a raid's "raid:", a location's or room's "loc:", a mod's "mod:", each with its name), so favourites, recent and links never mistake it for a prefab of the same name. Items only creatures carry, which nothing a player meets gives, go last under *Carried by creatures*; before them, *Creature attacks* holds the attack items creatures carry, and *Attacks no creature carries* the like that no creature carries, left in the game's data (the Jotun warriors' clubs, a spirit bjorn's unused swipe). An attack item is one with nothing to see or hear, or a weapon with no icon: no inventory can show an item without one (`ItemData.GetIcon` reads it by the item's variant), so no player holds it, whatever recipe or source a mod gives it. Gear without an icon that a creature carries goes under *Carried by creatures*. What is under either is tagged with the creatures carrying it (`AttackTags`), one or two named, more counted, a creature and its variants going by one name counted once; things of one kind and name are told apart by that tag before their prefabs' words or a count (`Search.TellAlike`), "Bear · claws", and with the compendium on the carrier's name reads –– until met.

An entry goes by the name the game shows for it, starting with a capital and in words where it runs them together ("GrapplingHook" as "Grappling hook", `Naming.SpacedOut`), and where the game gives none by its prefab's words (`Entry.ShownName`, `Naming.Readable`: "arbalest_projectile_blackmetal" as "Arbalest projectile blackmetal"), without the makers' marks for an effect or a sound (vfx, sfx, fx), a sound or a visual ending with what it is so a creature's hit, its look and its sound do not go by one name ("sfx_troll_hit" as "Troll hit sound", "vfx_spawn" as "Spawn visual"), "aoe" as "area", and a word said twice in a row said once, as in rooms' names ("cave_shrine_shrine02" as "Shrine 02", `Naming.SaidOnce`), its prefab's name beside it in the list and under it on its page while the compendium is off; a mod goes by its name as it writes it. Such made-up names are no names a text holds, so the compendium never keeps them back in a page's text.

## Names of places

A place goes by the name the game shows on entering it (`Teleport.m_enterText`, "Burial Chambers") or discovering it (`Location.m_discoverLabel`). Otherwise an altar goes by its boss ("The Elder's altar") and a camp by its trader ("Haldor's camp"), and anything else by its prefab name in words, without variant numbers and the makers' tags, with creatures called as the game calls them ("GoblinCamp2" is a Fuling camp). Each place says its biomes from the world's location list. A dungeon room goes by the dungeons built with its kind of room (`DungeonGenerator.m_themes` against `Room.m_theme`), so a crypt's rooms and its entrance are one place. The `in:` search looks at a place's name, not its biome.
