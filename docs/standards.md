# Standards

The rules every change keeps, from wording and numbers to colours and doc comments, and the tests over the source that hold each one.

Code: `src/Model/Naming.cs`, `src/UI/Skin.cs`, `src/Model/Numbers.cs`, `src/Model/Stored.cs`, `src/Model/PanelPlace.cs`, `src/Model/ChipFlow.cs`, `src/UI/ScryPanel.Drawn.cs`.

See also: [architecture](architecture.md), [index](index.md); all notes in [the index](index.md).

## Text, numbers, styles and the tests that hold them

Text is English whatever the PC is set to. Every number shown, in the panel and in the log, becomes text through `Numbers`, its thousands by commas, and comments and these notes write a thousand or more with commas too, as a test holds; what Scry writes into its own files and keys to read back, and every number it reads from text, goes through `Stored` (the panel's place in `PanelPlace`); a list reads through `Naming.Joined`, names with commas through `Naming.Commas`, a title with how many it holds through `Naming.Counted`, a multiplier ("×1.5") through `Numbers.Times` and a text begun with a capital through `Naming.Capital`, the last two as tests hold, and a tip's lines one under another through `Naming.Lines`; and string checks compare ordinally. The tests in `tests/Scry.Tests/Standards` compile the whole source and the self-test with the compiler's own types (`ScrySource`) and fail at each place a standard is not kept, implicit ones too, such as a count in an interpolated string. Comments and documents say what a part does and why, in the same plain words as the panel. The build fails for a comment that links to something gone or names parameters wrongly, a test fails for a doc comment over no member or two over one (`DocStandardTests`), and the build for any finding of the .NET code analysis rules, all of which run but the few `Analysis.globalconfig` turns off, each with its reason (`BuildChecks.props`, shared by Scry and the self-test); a test fails for a name in these notes, or a search example in the README, that the source no longer has.

The panel lays out every row of chips, tabs, buttons and segments by one flow (`ChipFlow`), a long list ending in one chip for the rest, and every labelled row (a slider, segments, toggles) with its label in one column (`RowLabel`). Its colours are the skin's, each named once in `Skin` or made there from one (`Skin.Alpha`, `Skin.Shade`, `Skin.Lift`), and so are its text styles, made together and made again together when the panel's scale changes; a label in a colour of its own is drawn one way (`Skin.LabelIn`), and a test fails for a colour or a style the panel makes elsewhere. A test also fails for a character lost on the way (U+FFFD) in any of the repository's own files. Scry offers no API, so every type is internal but the plugin classes BepInEx loads, as a test holds. The self-test is a plugin of its own; what it reads from Scry is a view of real state or how often a part of the panel was drawn (`ScryPanel.Drawn`, counted on repaint), and where only a click opens a box, a small opener sets what the click would (`ShowHelp`, `OpenViewMenu`, `OpenSlider`); nothing else is added for it.

No method of Scry's or the self-test's runs longer than 120 lines and no file longer than 1,000 (`SizeStandardTests`): those already longer are listed with the lines each holds, may shrink but never grow, and leave the list once short enough, the test saying so, so the list only gets shorter.

A member of Scry's that only the self-test uses is a hook: marked `[ForTest]` (`ForTestAttribute`) or named ending in ForTest (`SelfTestHookStandardTests`). Scry's own code calls no hook method but from another hook and touches no marked member, so what a player runs never takes a path only the self-test should; a property named a hook may still be written by Scry for the self-test to read, or read for what the self-test stands in with.
